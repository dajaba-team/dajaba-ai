# 00. 태깅 공통 기준 (블라인드 사본 — SCRUM-281)

2차 두 사람 태깅(`03_sampling.md`)에서 **태깅하는 사람에게 주는 유일한 기준 문서**. 유형 정의·조건·함정만 있고 **문서·쪽·문장 위치, 후보, 확신, 판정 예시는 없다**. 위치별 판단이 들어 있는 `01_term_map.md`·`02_untagged_review.csv`(AI 보조 초안)는 두 사람 태깅이 끝난 뒤에 연다.

## 유형 — 그래프 패턴이 문장에 있어야 붙인다

| 유형 | 문장에 있어야 하는 것 |
|---|---|
| FAN_IN | 여러 출처(사람·계좌) → **같은 한 계좌(또는 한 수취인)** 로 돈이 모임 |
| FAN_OUT | **같은 한 계좌** → 여러 계좌·수취인으로 돈이 퍼짐 |
| CYCLE | 같은 돈이 계좌(또는 은행)들을 거쳐 **출발 계좌로 돌아옴** |
| SCATTER_GATHER (SG) | **한 계좌** → 여러 계좌로 퍼졌다가 → **그 여러 계좌에서** 다시 **한 계좌**로 모임 (퍼진 계좌들과 모이는 계좌가 문장에서 이어져야 함) |
| GATHER_SCATTER (GS) | 여러 곳 → **같은 한 계좌로 모였다가 → 그 계좌에서** 여러 곳으로 퍼짐 (모이는 계좌와 퍼지는 계좌가 같은 하나여야 함) |
| 없음 | 위 구조가 문장에 없음 |

여러 개 붙을 수 있다 — 예: 여러 출처 → 같은 한 계좌로 모이고 **모인 그 계좌에서** 여러 곳으로 퍼지면 FAN_IN 과 GS. 모이는 계좌와 퍼지는 계좌가 **다르거나 이어지는지 문장에 없으면** 각각 FAN_IN·FAN_OUT 만 붙이고 GS 는 아니다.

## 공통 조건

1. **계좌 사이 흐름**: 송금·입금·이체·수표 같은 이체 간선이 문장에 있어야 한다. 모이는 곳(FAN_IN·GS)이나 퍼지는 출발점(FAN_OUT·SG)이 **계좌(또는 수취인) 하나로** 문장에 있어야 한다. "그 사람의 계좌들"·"셸 회사 계좌들"처럼 여럿으로만 적혀 있으면 하나로 보지 않는다(다수 → 다수). **GS 는 모인 그 같은 계좌가 퍼지는 출발점이기도 해야 하고, SG 는 퍼지는 출발 계좌 하나와 다시 모이는 계좌 하나가 문장에서 이어져야 한다.**
2. **그 청크 안에서**: 유형을 보여 주는 부분이 태깅하는 청크 범위 안에 있어야 한다. 앞뒤 청크에만 있으면 "없음".
3. 용어가 나와도 구조가 없으면 "없음" — 단계 이름·정의·열거만 있는 문장은 유형이 아니다.

## 아님 (함정)

- 범죄 수익을 범죄자·의뢰인·소유주에게 **돌려주는** 통합 단계 → CYCLE 아님(출발 계좌로의 순환이 아님)
- 상품-현금 치환(무역 송장 조작·상품 재수출), 카지노 칩 전달·환전, 우편환끼리 교환, 현금을 사람에게 넘김 → 계좌 흐름 아님
- 현금 통제망·계정 상계(여러 곳 → 여러 곳으로 맞춰 정산) → FAN_IN·CYCLE 아님
- 지하은행식 가치 치환(돈이 실제로 이동하지 않고 장부로 상계) → 아님
- **한 사람이 여러 지점·여러 번 나눠 넣는 분할**(structuring) → 출처가 하나라 FAN_IN 아님. 여러 사람·여러 계좌가 같은 한 계좌로 나눠 보낼 때만 FAN_IN
- 받는 쪽이나 출발점이 문장에 없는 다수 → 다수 이체 → 아님
- 사업 모델·회사 역할 설명(결제대행이 무엇인지 등) → 아님

## 용어 → 유형 (일반 규칙, 위치·예시 없음)

| 용어 | 기본 | 이럴 때만 유형 |
|---|---|---|
| funnel account | FAN_IN | 여러 곳·여러 사람 입금이 같은 한 계좌로 모임 (그 같은 계좌에서 여러 곳으로 퍼지기까지 문장에 있으면 GS 도) |
| pass-through account · 경유 계좌 | 없음 | 여러 출처 → 같은 한 경유 계좌면 FAN_IN · 그 같은 계좌 → 여러 수취까지 이어질 때만 GS · 한 계좌 → 여러 수취만 있으면 FAN_OUT (받아 넘기기만 하는 1:1 사슬은 아님) |
| money mule | 없음 | 여러 피해자 송금이 같은 한 뮬 계좌로 모이면 FAN_IN (뮬 계좌가 여럿으로만 적혀 있으면 아님) |
| money mule network | 없음 | 피해자들 → **같은 한 뮬 계좌** → 그 계좌에서 여러 곳이면 GS (뮬 계좌가 여럿으로만 적혀 있으면 아님) |
| layering · smurfing | 없음 | 구조가 따로 문장에 있을 때만 |
| structuring · 분산 거래 · 분할(쪼개기) | 없음 | 여러 사람·계좌 → 같은 한 수취인이면 FAN_IN (국문 "분산 거래" 는 보고 회피 분할 뜻 — "퍼짐"이 아님) |
| round-tripping | 없음 | 같은 돈이 출발 계좌로 돌아오면 CYCLE |
| kiting(융통어음화) | 없음 | 두 계좌 사이 수표 왕복으로 출발 계좌로 돌아오면 CYCLE |
| nesting | 없음 | (계좌 빌려주기 구조 — 그래프 유형 아님) |
| commingling · 자금 집중 | FAN_IN | 여러 출처 자금이 같은 한 계좌로 모임 |
| consolidation · holding account | FAN_IN | 여러 곳 → 같은 한 보관 계좌면 FAN_IN · 그 같은 계좌에서 뒤이어 여러 곳으로 보내면 GS 도 |
| multiple beneficiaries · re-distribution | 없음 | **같은 한 계좌**에서 이체로 여러 곳에 보내면 FAN_OUT (출발 계좌가 여럿이면 다수 → 다수) |
| 차명계좌 · 대포통장 · nominee account | 없음 | 명의 문제만으로는 유형 아님 — 흐름으로 따로 정함 |
| third-party checks | 없음 | 제3자 수표 여러 장이 같은 한 계좌로 들어가면 FAN_IN |

## 적는 법

- 청크마다 유형(여러 개 가능) 또는 "없음", 그리고 근거 위치 `p쪽·s문장`. 문장 순번 = 그 쪽 `get_text()` 를 NFKC 로 바꾼 뒤 문장 끝(`.`·`?`·`!` — 국문 `다.` 포함) + 공백, 또는 빈 줄에서 나눈 1부터 순번.
- 원문 문장은 시트에 옮기지 않는다(10_rag 이용 조건 ①). 판단 이유는 짧게 한국어로.
