# 01. 용어 대응표 초안 — 공개 자료 용어 → 우리 유형 (SCRUM-281, RAG 2차 태그 검수용)

공개 규제 자료는 우리 유형 이름(FAN_IN·FAN_OUT·CYCLE·SCATTER_GATHER·GATHER_SCATTER)을 쓰지 않는다. 특히 **SG·GS 는 규제 용어가 아니라 합성 데이터(IBM·AMLSim) 이름**이라, 태그 기준보다 이 표가 먼저다(10_rag "2차로 넘기는 것" 2번). **초안이고 적용 0** — manifest·DB 태그는 바뀌지 않는다(09 2026-11-19 SCRUM-281).

- **이 표와 `02` 의 후보·근거 위치는 AI 보조로 만든 초안이다(사람 확인 전).** 청크를 읽고 판단한 결과를 사람이 아직 PDF 로 확인하지 않았다 — 2차 두 사람 태깅(`03`)의 출발점일 뿐 정답이 아니다.
- **블라인드**: 이 파일에는 위치별 판단(근거 위치·확신)이 들어 있어 **두 사람 태깅이 끝날 때까지 열지 않는다**. 태깅 기준으로는 위치·판단 예시를 뺀 공통 기준 사본 `00_tagging_criteria.md` 만 쓴다(`03` 4절).
- **유형 판단 기준은 10_rag "코퍼스 태그 근거" 와 같다** — 그래프 패턴(한 계좌로 모임 / 한 계좌에서 퍼짐 / 출발 계좌로 돌아옴 / 퍼졌다 모임 / 모였다 퍼짐)이 **문장에 있어야** 그 유형. 용어가 나와도 구조가 없으면 "없음". 범죄 수익을 의뢰인에게 돌려주는 통합 단계·상품-현금 치환·현금 통제망·상계는 아님.
- **계좌 사이 흐름**(추가 검토 1 반영): 송금·입금·이체·수표 같은 **이체 간선**이 문장에 있고, 모이는 곳(FAN_IN·GS)이나 퍼지는 출발점(FAN_OUT·SG)이 **계좌(또는 수취인) 하나**로 문장에 있어야 후보 — "계좌들"로만 적히면 다수 → 다수로 봄, GS 는 모인 그 같은 계좌에서 퍼져야 함(추가 검토 2 반영). 칩 전달·환전, 현금을 사람에게 넘김, 우편환끼리 교환, 받는 쪽·출발점이 없는 다수→다수는 아님. 한 사람이 여러 지점에서 나눠 넣는 분할은 출처가 하나라 FAN_IN 아님. 근거 문장의 유형을 보여 주는 부분이 **그 청크 본문 안에** 있어야 함(이웃 청크에만 있으면 후보 없음).
- **원문은 옮기지 않는다**(10_rag 이용 조건 ①). 근거는 위치만 — `doc_id p쪽 s문장`. 쪽 = PDF 쪽(1부터). 문장 순번 = 그 쪽 `pymupdf` `get_text()` 를 NFKC 로 바꾼 뒤 문장 끝(`.`·`?`·`!` — 국문 `다.` 포함) + 공백, 또는 빈 줄에서 나눈 1부터 순번. "용어" 는 짧은 명사구만.
- "근거 위치" 의 **낱말** = 그 낱말이 문장에 그대로 있음 · **개념** = 낱말은 다르지만 그 뜻의 구조가 있음(국문 문서·다른 표현). **코퍼스 없음** = 8개 문서 어디에도 낱말·개념이 없음. **제외 예** = 비슷해 보이지만 위 기준으로 뺀 위치.
- 바깥 공식 링크(열림 확인 11/19): FinCEN [SAR Advisory Key Terms](https://www.fincen.gov/resources/suspicious-activity-report-sar-advisory-key-terms) · FinCEN [Advisory FIN-2014-A005](https://www.fincen.gov/resources/advisories/fincen-advisory-fin-2014-a005). FATF glossary·FFIEC·FBI 페이지는 자동 확인이 막혀(403) 넣지 않았다.
- 확신: **높음** = 대응이 문장 구조로 분명 · **낮음** = 해석이 필요하거나 근거가 하나뿐·코퍼스 없음.

## SG·GS — 대응하는 공개 용어

- **SCATTER_GATHER(한 곳 → 여럿 → 다시 한 곳)**: 대응하는 공개 용어 **없음**, 후보 0. 구조만 비슷해 보인 2곳은 계좌 사이 흐름이 아니어서 뺐다(`fincen-sar-narrative-2003` p31 — 칩 전달·환전을 거쳐 합류 · `fatf-pml-2018` p33 — 출발이 현금). 10_rag 의 "R05 → references=[]" 판단과 같은 결 — 억지로 채우지 않는다.
- **GATHER_SCATTER(여럿 → 같은 한 계좌 → 그 계좌에서 여럿)**: 고정된 공개 용어는 없고 **consolidation(holding) account 사례**에서 구조로만 나온다 — 후보 1곳(`fatf-pml-2018` p48 s6-7, 피해 대금 → 보관 계좌 하나 → 여러 사기범, 높음). money mule network 사례(p25 s9-10)는 뮬 계좌가 여럿이라 뺐다(추가 검토 2). `fincen-money-mule-2020` 은 뮬 정의·모집 수법뿐이라 GS 근거 없음(p6~7 지표 목록은 PDF 추출이 거의 빈 줄 — 원본 PDF 로 2차에서 다시 볼 것).
