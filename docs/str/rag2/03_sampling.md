# 03. 표본 뽑는 법 — 두 사람 태그 일치율 (SCRUM-281, RAG 2차 첫 작업용)

`02_untagged_review.csv`(태그 없는 398청크)에서 **60~80개**를 뽑아 두 사람이 서로 안 보고 유형 태그를 달고, 일치율로 태그 기준(공통 기준 사본 `00_tagging_criteria.md` — 10_rag "코퍼스 태그 근거" 와 같은 기준)이 사람마다 같게 읽히는지 본다. **이 문서는 방법만** — 뽑은 목록과 실제 태깅은 2차에서 한다(09 2026-11-19 SCRUM-281).

- **`02` 의 후보 유형·근거·확신·메모는 AI 보조로 만든 초안(사람 확인 전)** 이다. 표본 태깅의 정답이 아니며, 두 사람에게는 보여 주지 않는다(4절).
- 위치 표기: `doc_id · page(PDF 쪽, 1부터) · 쪽 안 문장 순번`. 문장 순번 = 그 쪽 `pymupdf` `get_text()` 를 NFKC 로 바꾼 뒤 문장 끝(`.`·`?`·`!` — 국문 `다.` 포함) + 공백, 또는 빈 줄에서 나눈 1부터 순번(`00`·`01` 과 같은 규칙).
- 원문은 표본 시트에도 옮기지 않는다 — 태깅하는 사람이 PDF 해당 쪽을 직접 연다(10_rag 이용 조건 ①).

## 1. 모집단과 층

| 층 | 나누는 기준 | 값 |
|---|---|---|
| 문서 | `doc_id` | 7개(태그 없는 청크가 있는 문서 — `fincen-funnel-2014` 은 0) |
| 후보 유무 | `02` 의 후보 유형 칸(`후보유형_AI보조초안_사람확인전`)이 비었나 | 있음 / 없음 |
| 검토 상태 | `02` 의 "검토 상태" | 검토 / 미검토 (미검토는 후보 "없음" 층에 넣되 따로 셈) |
| **새 3문서**(SCRUM-306 ★B-4) | SCRUM-305 로 들어온 `apg-typologies-2025`·`fincen-cmln-2025`·`fintrac-underground-banking-2023` 의 **무태그 청크** — 305 쪽 단위 태그 밖, `02` 에 없어 **AI 보조 후보 없음** | 259(apg 223 · cmln 32 · fintrac 4, DB 무태그와 같음) |

새 3문서 층을 두는 이유: 나중 "LLM 후보 + 사람 확인" 단계(10_rag 2차 2번)가 새 문서에도 두 사람 κ 근거를 갖게. 기존 70행(1~3절)은 그대로 두고 이 층 10행을 덧붙여 **80행**.

## 2. 몇 개를 어디서

목표 **70개**(60~80 안).

1. **후보 있음 층**: 후보 있는 행이 35개 이하면 **전부**, 넘으면 35개를 문서 비율대로. (11/19 추가 검토 2회 반영 뒤 후보 있는 행 16 → 전부, 후보 없음 층 54)
2. **후보 없음 층**: 나머지(70 − 1번 수)를 문서별 **후보 없음 층** 청크 수 비율(분모 = 후보 없음 층 전체, 11/19 기준 382 — SCRUM-306 ★A)로 나누되 **문서마다 최소 2개**(국문 `fincen-msb-ko-2007` 은 최소 4개 — 국문 용어 일치율을 따로 보려고). 미검토 행도 이 층에서 같이 뽑는다(키워드가 놓친 후보가 있는지 보는 몫).
3. 반올림으로 70 을 넘거나 모자라면 가장 큰 문서(`fatf-tbml-2020`) 몫에서 맞춘다.

4. **새 3문서 층 10개**: 문서별 무태그 청크 수 비율, **문서마다 최소 2개**(반올림은 사사오입, 넘치거나 모자라면 가장 큰 문서 `apg-typologies-2025` 몫에서 맞춤) → apg 6 · cmln 2 · fintrac 2.

후보 있음 비율이 지나치게 높으면(70 중 절반 넘음) 두 사람이 "후보 칸이 있던 표본이 많다"는 걸 짐작할 수 있으니, 1번 상한 35 를 지킨다.

## 3. 뽑는 순서 (재현 가능하게)

- **시드 고정 `281`**(이슈 번호). 층마다 `chunk_id` 로 정렬한 목록에서 `random.Random(281).sample(목록, k)` — 층 순서는 문서 `doc_id` 사전순 → 후보 있음 → 없음. **난수열은 하나**(`Random(281)` 을 한 번 만들어 층 순서대로 이어 씀 — 304 추출과 같은 방식, SCRUM-306). 목록 파일의 행 순서는 층이 드러나지 않게 `doc_id · page · 쪽 안 청크 순번` 순(후보 있음 행이 앞에 몰리지 않게). 80행이 된 뒤에는 두 사람 시트(묶음)를 80행 전체 `doc_id · page · 순번` 순으로 섞어 만든다 — 새 3문서 행이 뒤에 몰리지 않게.
- **새 3문서 층(4번)**: 모집단은 `02` 가 아니라 `corpus/pdf/` 재분할 + manifest `typology_pages` 로 태그가 없는 청크(= DB 무태그 259). **시드 `306`** 으로 `Random(306)` 한 난수열을 문서 `doc_id` 사전순으로 이어 쓰고, 문서마다 `chunk_id` 정렬 목록에서 `sample`. 뽑은 10행은 기존 70행 **뒤에 덧붙임**(앞 70행은 바이트까지 그대로). 도구 `tools/rag2_sample_new.py`.
- 뽑은 목록 파일은 `docs/str/rag2/05_sample.csv`(SCRUM-306 — 가칭이던 `04` 는 304 확인자 기준서 `04_checker_guide.md` 와 번호가 겹쳐 05) — 칸은 `chunk_id · doc_id · page · 쪽안_청크순번 · 시작 · 끝` **만**. **쓰기·80행 전체 대조는 `tools/rag2_sample_new.py` 하나**(`--write`) — `tools/rag2_sample.py` 는 기존 70행 층을 계산해 05 앞 70행과 대조만 하고 쓰기 함수가 없다(추가 검토 1·2회차). 쓰기 전 검사: 고유한 80행 · 앞 70행(머리글 포함) sha256 = 동결 값 `773ba999…` · 기존 05 가 있으면 내용이 같을 때만 그대로 두고(다르면 중단) · 없을 때만 임시 파일 → 원자 교체로 씀.
- **청크 경계(추가 검토 2 반영)**: 청크는 문자 예산·겹침으로 문장 중간에서도 끊기므로 쪽·순번만으로는 범위를 알 수 없다. 목록을 만들 때 `corpus/pdf/` + `tools/corpus_chunks.chunk_pdf_pages` 로 다시 나눈 결과에서 **그 쪽 `get_text()` 를 NFKC 로 바꾼 추출문 기준 청크 시작·끝 문자 오프셋**(0부터, 끝은 포함 안 함)을 넣고, 같은 재분할의 `compute_content_hash` 가 목록의 `chunk_id` 와 **모두 일치하는지 확인**한 뒤 나눠 준다(하나라도 다르면 멈춤). 태깅하는 사람은 그 범위 안 문장만 본다 — 이웃 청크 문장은 근거로 쓰지 않는다. 오프셋은 `05_sample.csv` 의 `시작`·`끝` 칸(SCRUM-306).
- **표본 시트 `문장범위` 칸(SCRUM-306 ★B)**: 두 사람에게 주는 시트에만 `문장범위` 칸을 더한다 — 청크 `시작`·`끝` 이 걸친 첫·끝 문장 순번(`s3~s9`), 청크가 문장 중간에서 시작·끝나면 그 쪽에 `(중간)`(예 `s3(중간)~s9`, 한 문장 안이면 `s4(중간)~s4(중간)`). 문장 나누기는 위 규칙을 이렇게 고정: NFKC 쪽 텍스트를 정규식 `(?<=[.?!])\s+` 또는 `\n\s*\n` 자리에서 나누고, 공백뿐인 조각은 세지 않음, 문장 범위 = 앞뒤 공백을 뺀 조각. 원문 0 — 숫자만. `05_sample.csv` 칸은 그대로 6개.
- **PDF 전달(SCRUM-306 ★B · ★B-4)**: 표본 문서 PDF 10개(기존 7 + 새 3)는 모두 **진희가 파일로 보낸다**(같은 sha256 이어야 쪽·오프셋이 맞음 — `ffiec-redflags` 공식 주소는 PDF 가 아닌 웹 페이지, FATF 는 자동 요청이 막힘). 쪽 안내에는 공식 주소를 **출처**로만 적고, 받는 곳은 "진희가 보낸 파일(sha256)". 범위 보기 스크립트(`tools/rag2_show_chunk.py` — 리포 import 없음, 자기 PDF 에서 그 범위만 화면에 띄움, 저장 0)를 같이 준다. 출력은 범위 안 문장마다 앞에 `[s번호]`(시작·끝이 문장 중간이면 `[s36(중간)]`) — 번호는 `문장범위` 와 같은 계산(문장 나누기 코드는 이 스크립트 한 곳에만 있고 묶음 도구가 가져다 씀). 쪽 안내에 실행 방법 3줄(`pip install pymupdf` · 명령 예 · 출력의 `[s번호]` 를 `근거위치` 에 그대로).
- **블라인드**: 두 사람에게 주는 것은 **두 가지뿐** — ① 이 목록(= `02` 에서 후보 유형·근거 위치·근거 용어·확신·메모 칸을 숨긴 사본) ② 태깅 기준 **공통 기준 사본 `00_tagging_criteria.md`**(유형 정의·조건·함정만, 위치별 후보·확신·판정 예시 0). **`01_term_map.md`·`02_untagged_review.csv` 원본은 두 사람 태깅이 모두 끝난 뒤에 연다** — 둘 다 위치별 AI 보조 판단이 들어 있어 보면 같은 판단으로 끌려가고 κ 가 독립적인 일치율이 아니게 된다.

## 4. 태그 다는 법 (두 사람, 서로 안 봄)

- 각자 PDF 해당 쪽을 열고, 그 청크 범위 문장에서 `FAN_IN · FAN_OUT · CYCLE · SG · GS · 없음` 중 해당하는 것 전부(여러 개 가능). 기준은 **`00_tagging_criteria.md` 만**(그래프 패턴·계좌 사이 흐름이 그 청크 문장에 있어야 함, 통합 단계 "돌려줌"·상품-현금 치환·칩·현금 전달은 아님). `01` 은 이 단계에서 보지 않는다.
- 태그마다 근거 위치(쪽·문장 순번)를 적는다. 원문은 안 옮긴다.
- 끝날 때까지 서로의 시트·`02` 후보 칸을 보지 않는다.
- **두 사람은 SCRUM-275 평가 세트 정답 확인자와 다른 사람**(09 2026-11-19 "SCRUM-275 정답 확인자 조건") — 정답 확인 때 425청크를 유형별로 본 판단이 블라인드 태깅에 섞이지 않게. **SCRUM-305 확인자와도 다른 사람**(09 2026-11-20 SCRUM-306) — 305 에서 유형별 청크를 등급 매긴 판단이 섞이지 않게.

## 5. 일치율 계산

유형이 여러 개 붙을 수 있어서 **유형마다 따로** 예/아니오 두 값으로 본다.

| 무엇 | 계산 |
|---|---|
| 유형별 κ | 유형 하나(예: FAN_IN)에 대해 70개 각각 두 사람이 "붙임/안 붙임". 관찰 일치 `p_o` = 같은 답 비율, 우연 일치 `p_e` = `p_A(붙임)·p_B(붙임) + p_A(안)·p_B(안)`, **Cohen's κ = (p_o − p_e) / (1 − p_e)** |
| 후보 유무 κ | "유형 하나라도 붙임 / 없음" 으로 같은 계산 — 2차 검색 필터에 가장 직접 걸리는 값 |
| 같이 적을 것 | 유형별 두 사람 "붙임" 수, 단순 일치율 `p_o` — 붙임이 5개 미만인 유형은 κ 가 크게 흔들리므로 κ 대신 수와 `p_o` 로 본다(**두 사람 중 적은 쪽 붙임 수 < 5** 이면 κ 칸을 비움 — SCRUM-306. `p_e = 1` 이면 κ 정의 안 됨, 비움) |

- **기존·새 문서 나눠 보기(SCRUM-306 ★B-4)**: 두 사람 κ 는 80행 전체 + 기존 8문서 70행 + 새 3문서 10행 따로. 새 3문서 10행은 행이 적어 κ 가 크게 흔들림 — 수·`p_o` 위주로 본다.
- **새 3문서 행 대 305**: 새 3문서 행의 합의 태그 중 CYCLE·SG·GS 를 305 확인 등급(≥ 1 / 0 / 확인 안 함)과, 305 LLM 초벌 등급(`answer_draft_corpus.json`, ≥ 1 / 0)과 비교표로 덧붙인다. 무태그 259 는 305 확인 범위(후보 쪽) 밖이라 확인 등급은 모두 "확인 안 함", 초벌은 세 유형 모두 0 — 합의가 붙이면 그 수가 "305 가 놓친 수".
- **AI 후보와 사람의 일치는 따로 잰다**(**기존 70행만** — 새 3문서 행은 `02` AI 보조 후보가 없음, 한계): 6절로 정한 사람 합의 태그를 정답으로 두고, `02` 의 AI 보조 후보와 유형별로 같은 2×2 표·κ(그리고 유형별 놓친 수·잘못 붙인 수)를 계산한다. 이 값은 두 사람 사이 κ 에 섞지 않는다 — 10_rag 2차 2번 "LLM 후보 비교" 의 첫 숫자.
- 해석(Landis·Koch 관례): 0.61~0.80 상당한 일치, 0.81 이상 거의 완전. **목표 κ ≥ 0.6**(후보 유무 κ 와, 붙임 5개 이상인 유형마다).
- 계산은 손으로 해도 되는 크기(2×2 표). 도구는 `tools/rag2_agreement.py`(SCRUM-306 — 받은 시트 검사·κ·불일치 목록·AI 대 합의, 출력은 chunk_id 만).
  - **받은 시트 검사**(하나라도 걸리면 계산 안 함): 칸 이름·순서가 묶음 시트와 다름 · 행 빠짐·더함·chunk_id 중복 · chunk_id 순서나 05 칸·`문장범위` 값이 묶음과 다름 · `태그` 빈 칸 · 모르는 태그(`FAN_IN·FAN_OUT·CYCLE·SG·GS·없음` 밖) · `없음` 과 다른 태그를 같이 · `없음` 이 아닌데 `근거위치` 빈 칸 · **행마다 셀 수 ≠ 머리글 칸 수**(쉼표가 섞여 칸이 밀린 행 — 태깅·결정·등급 시트 공통 판독기) · **`근거위치` 가 그 행 밖**: 조각(`;` 로) 마다 `p쪽 s번호[(중간)][~s번호[(중간)]]` 꼴(쪽과 문장 사이는 공백 또는 가운데점 `·` — 00 기준서 예시 `p쪽·s문장` 과 묶음 안내 `p15 s19` 둘 다, 예시 통일은 다음 배포본)이고, 쪽 = 그 행 `page`, 문장 번호가 그 행 `문장범위` 안(태그 있는 행은 필수, `없음` 행에 적힌 근거도 있으면 같은 검사 — 태그·근거를 다른 행으로 옮긴 시트를 막음) · **두 시트가 행마다 태그·근거위치·메모까지 전부 같음**(같은 사람 시트를 다시 저장한 사본 — 바이트만 비교하면 BOM 하나로 통과). 비교 전 정규화: 셀 안 줄바꿈 CRLF → LF · 앞뒤 공백 · 근거위치는 (쪽, 첫 문장, 끝 문장) 목록으로. **오류 메시지는 파일명·행 번호·칸 이름(번호)만** — 받은 셀 값(본문·근거·태그 글자)은 stdout·stderr 어디에도 안 냄. 다음 회차에는 태그 칸에도 등급 칸처럼 행 ID(`ID=태그`)를 넣는다 — 이번 시트는 이미 돌아와 근거위치 검사로 대신(알고 남김)

## 6. 일치 안 하면

1. **두 사람이 다르게 단 행은 확인자(김종민)가 정한다**(SCRUM-306 — 설계자 진희는 태그·등급 판단을 하지 않음, 09 2026-11-20) — 기준 문서(10_rag·01) 어느 줄에 따라 정했는지 한 줄 남긴다. 다수결로 정하지 않는다(두 명뿐).
2. 어긋난 이유를 셋 중 하나로 분류: **기준이 모호**(01·10_rag 문구 고침) / **용어 오해**(01 "뜻이 다른 쓰임" 칸 보강) / **단순 실수**(고칠 것 없음).
3. **κ < 0.6** 인 유형(또는 후보 유무 κ < 0.6)은 기준 문구를 고친 뒤 **새로 20개**를 같은 방법(시드 `2811`)으로 뽑아 다시 태그 → κ 재계산. 두 번째도 0.6 미만이면 그 유형은 LLM 후보 비교(10_rag 2차 2번)로 넘기지 않고 회의 안건으로.
