# 03. 표본 뽑는 법 — 두 사람 태그 일치율 (SCRUM-281, RAG 2차 첫 작업용)

`02_untagged_review.csv`(태그 없는 398청크)에서 **60~80개**를 뽑아 두 사람이 서로 안 보고 유형 태그를 달고, 일치율로 태그 기준(공통 기준 사본 `00_tagging_criteria.md` — 10_rag "코퍼스 태그 근거" 와 같은 기준)이 사람마다 같게 읽히는지 본다. **이 문서는 방법만** — 뽑은 목록과 실제 태깅은 2차에서 한다(09 2026-11-19 SCRUM-281).

- **`02` 의 후보 유형·근거·확신·메모는 AI 보조로 만든 초안(사람 확인 전)** 이다. 표본 태깅의 정답이 아니며, 두 사람에게는 보여 주지 않는다(4절).
- 위치 표기: `doc_id · page(PDF 쪽, 1부터) · 쪽 안 문장 순번`. 문장 순번 = 그 쪽 `pymupdf` `get_text()` 를 NFKC 로 바꾼 뒤 문장 끝(`.`·`?`·`!` — 국문 `다.` 포함) + 공백, 또는 빈 줄에서 나눈 1부터 순번(`00`·`01` 과 같은 규칙).
- 원문은 표본 시트에도 옮기지 않는다 — 태깅하는 사람이 PDF 해당 쪽을 직접 연다(10_rag 이용 조건 ①).

## 1. 모집단과 층

| 층 | 나누는 기준 | 값 |
|---|---|---|
| 문서 | `doc_id` | 7개(태그 없는 청크가 있는 문서 — `fincen-funnel-2014` 은 0) |
| 후보 유무 | `02` 의 후보 유형 칸(`후보유형_AI보조초안_사람확인전`)이 비었나 | 있음 / 없음 |
| 검토 상태 | `02` 의 "검토 상태" | 검토 / 미검토 (미검토는 후보 "없음" 층에 넣되 따로 셈) |

## 2. 몇 개를 어디서

목표 **70개**(60~80 안).

1. **후보 있음 층**: 후보 있는 행이 35개 이하면 **전부**, 넘으면 35개를 문서 비율대로. (11/19 추가 검토 2회 반영 뒤 후보 있는 행 16 → 전부, 후보 없음 층 54)
2. **후보 없음 층**: 나머지(70 − 1번 수)를 문서별 청크 수 비율로 나누되 **문서마다 최소 2개**(국문 `fincen-msb-ko-2007` 은 최소 4개 — 국문 용어 일치율을 따로 보려고). 미검토 행도 이 층에서 같이 뽑는다(키워드가 놓친 후보가 있는지 보는 몫).
3. 반올림으로 70 을 넘거나 모자라면 가장 큰 문서(`fatf-tbml-2020`) 몫에서 맞춘다.

후보 있음 비율이 지나치게 높으면(70 중 절반 넘음) 두 사람이 "후보 칸이 있던 표본이 많다"는 걸 짐작할 수 있으니, 1번 상한 35 를 지킨다.

## 3. 뽑는 순서 (재현 가능하게)

- **시드 고정 `281`**(이슈 번호). 층마다 `chunk_id` 로 정렬한 목록에서 `random.Random(281).sample(목록, k)` — 층 순서는 문서 `doc_id` 사전순 → 후보 있음 → 없음.
- 뽑은 목록 파일은 2차에서 `docs/str/rag2/04_sample.csv`(가칭)로 — 칸은 `chunk_id · doc_id · page · 쪽 안 청크 순번 · 청크 시작·끝 위치` **만**.
- **청크 경계(추가 검토 2 반영)**: 청크는 문자 예산·겹침으로 문장 중간에서도 끊기므로 쪽·순번만으로는 범위를 알 수 없다. 목록을 만들 때 `corpus/pdf/` + `tools/corpus_chunks.chunk_pdf_pages` 로 다시 나눈 결과에서 **그 쪽 `get_text()` 를 NFKC 로 바꾼 추출문 기준 청크 시작·끝 문자 오프셋**(0부터, 끝은 포함 안 함)을 넣고, 같은 재분할의 `compute_content_hash` 가 목록의 `chunk_id` 와 **모두 일치하는지 확인**한 뒤 나눠 준다(하나라도 다르면 멈춤). 태깅하는 사람은 그 범위 안 문장만 본다 — 이웃 청크 문장은 근거로 쓰지 않는다. 오프셋 파일은 2차에서 만든다(지금은 없음).
- **블라인드**: 두 사람에게 주는 것은 **두 가지뿐** — ① 이 목록(= `02` 에서 후보 유형·근거 위치·근거 용어·확신·메모 칸을 숨긴 사본) ② 태깅 기준 **공통 기준 사본 `00_tagging_criteria.md`**(유형 정의·조건·함정만, 위치별 후보·확신·판정 예시 0). **`01_term_map.md`·`02_untagged_review.csv` 원본은 두 사람 태깅이 모두 끝난 뒤에 연다** — 둘 다 위치별 AI 보조 판단이 들어 있어 보면 같은 판단으로 끌려가고 κ 가 독립적인 일치율이 아니게 된다.

## 4. 태그 다는 법 (두 사람, 서로 안 봄)

- 각자 PDF 해당 쪽을 열고, 그 청크 범위 문장에서 `FAN_IN · FAN_OUT · CYCLE · SG · GS · 없음` 중 해당하는 것 전부(여러 개 가능). 기준은 **`00_tagging_criteria.md` 만**(그래프 패턴·계좌 사이 흐름이 그 청크 문장에 있어야 함, 통합 단계 "돌려줌"·상품-현금 치환·칩·현금 전달은 아님). `01` 은 이 단계에서 보지 않는다.
- 태그마다 근거 위치(쪽·문장 순번)를 적는다. 원문은 안 옮긴다.
- 끝날 때까지 서로의 시트·`02` 후보 칸을 보지 않는다.
- **두 사람은 SCRUM-275 평가 세트 정답 확인자와 다른 사람**(09 2026-11-19 "SCRUM-275 정답 확인자 조건") — 정답 확인 때 425청크를 유형별로 본 판단이 블라인드 태깅에 섞이지 않게.

## 5. 일치율 계산

유형이 여러 개 붙을 수 있어서 **유형마다 따로** 예/아니오 두 값으로 본다.

| 무엇 | 계산 |
|---|---|
| 유형별 κ | 유형 하나(예: FAN_IN)에 대해 70개 각각 두 사람이 "붙임/안 붙임". 관찰 일치 `p_o` = 같은 답 비율, 우연 일치 `p_e` = `p_A(붙임)·p_B(붙임) + p_A(안)·p_B(안)`, **Cohen's κ = (p_o − p_e) / (1 − p_e)** |
| 후보 유무 κ | "유형 하나라도 붙임 / 없음" 으로 같은 계산 — 2차 검색 필터에 가장 직접 걸리는 값 |
| 같이 적을 것 | 유형별 두 사람 "붙임" 수, 단순 일치율 `p_o` — 붙임이 5개 미만인 유형은 κ 가 크게 흔들리므로 κ 대신 수와 `p_o` 로 본다 |

- **AI 후보와 사람의 일치는 따로 잰다**: 6절로 정한 사람 합의 태그를 정답으로 두고, `02` 의 AI 보조 후보와 유형별로 같은 2×2 표·κ(그리고 유형별 놓친 수·잘못 붙인 수)를 계산한다. 이 값은 두 사람 사이 κ 에 섞지 않는다 — 10_rag 2차 2번 "LLM 후보 비교" 의 첫 숫자.
- 해석(Landis·Koch 관례): 0.61~0.80 상당한 일치, 0.81 이상 거의 완전. **목표 κ ≥ 0.6**(후보 유무 κ 와, 붙임 5개 이상인 유형마다).
- 계산은 손으로 해도 되는 크기(2×2 표). 스크립트를 쓰면 리포 밖 또는 2차 이슈에서.

## 6. 일치 안 하면

1. **두 사람이 다르게 단 행은 세 번째 사람(진희)이 정한다** — 기준 문서(10_rag·01) 어느 줄에 따라 정했는지 한 줄 남긴다. 다수결로 정하지 않는다(두 명뿐).
2. 어긋난 이유를 셋 중 하나로 분류: **기준이 모호**(01·10_rag 문구 고침) / **용어 오해**(01 "뜻이 다른 쓰임" 칸 보강) / **단순 실수**(고칠 것 없음).
3. **κ < 0.6** 인 유형(또는 후보 유무 κ < 0.6)은 기준 문구를 고친 뒤 **새로 20개**를 같은 방법(시드 `2811`)으로 뽑아 다시 태그 → κ 재계산. 두 번째도 0.6 미만이면 그 유형은 LLM 후보 비교(10_rag 2차 2번)로 넘기지 않고 회의 안건으로.
4. 정해진 태그는 **사람 승인 뒤에만** manifest·DB 에 적용(10_rag 2차 2번) — 이 표본 작업 자체로는 아무것도 바뀌지 않는다.
