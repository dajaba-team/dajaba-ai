# ML+DL 조사 순위

`GET /v1/dl-rankings/{scan_date}`는 인증된 내부 호출에 시연 스캔 전체의 조사 순위를 제공한다. 기준 스캔은 9/7이다. ML 점수가 있는 경보의 기본 순위는 rc3 점수 내림차순으로 정한다. 기본 순위가 동점이면 경보 번호 오름차순을 사용한다.

1. 근거 거래의 DL 점수가 모두 유효한 경보에서 거래 점수의 **최댓값**을 DL 경보 점수로 사용한다.
2. 완전 연결된 경보끼리 ML 점수와 DL 경보 점수를 각각 오름차순으로 순위화한다. 낮은 점수에 작은 내부 순위값을 주고, 점수가 같은 항목에는 그 위치들의 평균을 준다. 따라서 **내부 순위값이 클수록** 더 의심스럽다. 두 내부 순위값의 `max`를 결합값으로 사용하므로 두 모델 중 경보를 더 의심스럽게 본 모델의 순위가 반영된다.
3. 완전 연결된 경보가 차지하던 자리 안에서 결합값 내림차순으로 배치한다. 결합값 동점은 경보 번호 오름차순으로 정한다. DL 근거가 하나라도 빠진 경보는 기존 ML 순위 자리를 유지한다. API 응답의 `ml_rank`와 `fused_rank`는 표시 순위라 **1이 최상위**다.

평균이나 RRF 대신 이 규칙을 채택한 목적은 한 모델만 강하게 의심한 경보도 상위에 남길 수 있도록 하기 위해서다. 방법별 성능 우열은 비교 실험으로 확인한 범위가 없다.

## 거래 시각과 순위 검증

DL 점수의 거래 시각은 분 단위다. 경보 `reference_ts`의 분보다 앞선 거래만 DL 근거로 인정한다. 직전 분의 거래는 포함하고, 같은 분의 거래는 분 안의 순서를 보장할 수 없어 제외한다. 그 결과 근거 하나라도 연결되지 않으면 `INCOMPLETE_DL_EVIDENCE`로 표시하고 ML 순위 자리를 유지한다.

API는 SHA-256으로 검증한 스냅샷의 순위만 반환한다. 검증 결과는 프로세스당 최대 4개를 메모리에 보관한다. 캐시 적중 여부와 관계없이 요청마다 manifest 1개와 참조 파일 8개, 총 9개를 읽고 각 파일의 SHA-256을 확인한다. 같은 스냅샷이면 CSV 파싱과 순위 재계산만 건너뛴다. 파일이 달라지거나 사라지면 해당 캐시 항목을 무효화하고 `503 DL_RANKING_UNAVAILABLE`를 반환한다. 이 조회는 기존 채점 점수, HIGH 기준, 예측 저장과 별개다.
